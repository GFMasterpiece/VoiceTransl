# VoiceTransl 产品目标

> 状态：用户确认的产品方向；具体节点图行为仍需逐步讨论。本文描述目标效果，不代表当前版本已经实现。

## 产品愿景

最终的 VoiceTransl 应提供类似 ComfyUI 的可视化工作流编辑体验：用户可以在画布上配置处理工作流中的节点，通过调整节点及其连接来设定音频处理路径，并能独立配置各个节点的设置。

“类似 ComfyUI”指以节点和连线作为编排交互方式，不意味着要复制 ComfyUI 的全部能力、界面或执行语义。核心是让用户能看见并主动控制处理流程，而不是只能使用程序固定好的流水线。

## 目标体验

- **可视化编排：**工作流以画布和节点图表示，处理步骤及其先后/依赖关系能通过节点连接表达。
- **路径可配置：**用户能够按需要调整工作流上的节点和连接，以确定一次处理使用哪些步骤、按什么依赖路径执行。
- **节点独立配置：**每个节点有自己的配置入口和参数；修改某个节点时，不应意外覆盖其他节点的设置。
- **执行过程可理解：**运行时能看出当前工作流、正在执行的节点、各节点状态和结果；失败应定位到相关节点。
- **保留任务边界：**沿用项目内各音频任务相互独立的原则；为某个音频运行工作流，不应串改其他音频的任务或输出。

## 当前版本与目标的区别

当前前端工作区仍以固定的 `preprocess → asr → alignment → translation → export` 五阶段作为导航，各阶段有独立配置入口；它还不是可自由连接、增删节点的 ComfyUI 式图编辑器。现行阶段、任务和文件契约见[架构约定](architecture.md)、[前端工作流](frontend_workflow.md)和[多音频项目契约](voicetransl_multi_audio_project.md)。

## 初步验收方向

当该方向进入实施并细化后，至少应满足：

1. 用户能在可视化画布上查看当前工作流的节点和连接。
2. 用户可以对工作流进行受支持的节点/连接调整，并设置每个节点自己的配置。
3. 启动前能校验工作流结构及各节点配置；无效工作流不能启动，并能指出问题位置。
4. 运行状态、失败和产物能关联到具体节点；恢复任务使用启动时保存的工作流与节点配置快照。
5. 工作流配置和音频任务相互区分：编辑工作流不会静默改写已经运行的任务或其他音频。

此列表是高层验收方向。节点编辑能力、连线约束、画布交互和持久化格式需要形成具体设计后，才能作为最终实现验收标准。

可视化编辑器的待实现需求与待决策项整理在[节点工作流规格](../spec/workflow-editor.md)；该规格目前为 Draft。

## 尚待明确

- 是否支持分支、汇合、多输入/多输出节点、条件执行，以及循环；还是首版仅允许可编辑的有向无环图。
- 用户可否创建自定义节点，或只能从内置节点库选择；节点与 Provider 能力如何对应。
- 节点移动/删除/复制、连线校验、撤销重做、缩放和布局保存的首版范围。
- 工作流以项目、音频还是可复用模板为作用范围；更新工作流后，如何处理已有音频覆盖。
- 工作流版本、任务恢复、已运行快照和旧固定五阶段项目的兼容迁移方式。
- 图式编排是否取代现有阶段工作区，或与阶段详情/配置面板组合使用。

在这些问题确认前，不应把分支执行、循环、自定义节点或任意 DAG 描述为用户已经要求或当前已经支持的功能。
