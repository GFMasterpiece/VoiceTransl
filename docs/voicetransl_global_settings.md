# VoiceTransl 全局本地 ASR 设置

顶部服务状态旁的“设置”入口在项目列表、上传页和项目工作台均可使用。
它打开应用级模态框，只管理后端的 CrispASR 可执行文件路径与模型目录，
不属于项目或音频的 Pipeline 配置。

本地模型发现与选择位于项目的 ASR 配置弹窗，全局设置仍只管理两项路径。
模型列表读取当前进程已生效的目录，不读取尚待重启的保存值；详见
[CrispASR 模型发现](crispasr_provider.md#local-model-discovery)。源语言仍由用户手动指定。

## 使用与生效

1. 打开“设置”，查看设置路径、当前后端实际使用路径及环境变量管理状态。
2. 编辑可写字段，点击“检查”。检查使用当前草稿，不保存配置。
3. 保存通过校验的草稿。成功后显示是否需要重启后端。
4. 手动重启后端，使下一次应用启动读取保存的 YAML 和环境变量。

保存只原子更新实际配置文件 `app` 下的 `crispasr_executable` 和
`crispasr_model_dir`，保留其余配置。当前进程不会热切换 Provider，
已运行和已排队任务不受保存操作影响；界面不提供重启或取消任务动作。
手动重启应由用户选择合适时机进行，不应把重启本身解释为对运行任务无影响。

打开、检查和保存设置不会离开当前视图，不中断上传或 WebSocket 订阅。
关闭有未保存修改的模态框需要确认丢弃；模态框支持键盘操作、焦点约束与关闭后
焦点恢复，加载、检查、保存、只读原因和错误均明确展示。

## 配置来源与路径

部署时通过 `VOICETRANSL_CONFIG` 指定实际读取和保存的 YAML；未设置时默认使用
仓库的 `config/app.yaml`。不要只修改一个未被当前后端加载的同名文件。
`editable` 表示当前部署是否允许通过接口保存配置；无法安全保存时应展示只读原因。

两个字段分别可被下列环境变量覆盖：

- `VOICETRANSL_CRISPASR_EXECUTABLE`
- `VOICETRANSL_CRISPASR_MODEL_DIR`

环境变量优先于 YAML。受环境变量管理的字段在界面只读，接口不允许修改该字段；
保存另一个字段时不能把环境变量的有效值写回覆盖原有 YAML。
要修改受管理的字段，应由部署者调整环境变量并重启后端。

相对路径按配置加载器的同一根目录解析，为实际 YAML 文件目录的父目录
（`config/app.yaml` 对应仓库根目录）。
允许根目录同样按此规则解析。

设置接口的路径字段、`active` 和 `allowed_roots` 使用隐私表示：配置根目录内
显示可直接检查或保存的 `./...`；根目录外使用后端启动时固定授权根目录的
`@root/N[/suffix]` 别名，编号从 1 开始。真实绝对路径保留在后端。
这种表示不改变真实运行路径；别名只是现有允许范围的引用，不能扩大路径权限。
用户可明确手动输入允许范围内的绝对路径，但响应仍使用隐私表示。
外部修改指向未授权目录时，重启重新授权前仅显示 `@unavailable`，不泄露该目录。
此时仍可读取设置及最新版本；对该占位执行检查或保存返回 `422 PATH_NOT_ALLOWED`，
需由部署者授权并重启后端。`restart_required` 仍按真实路径是否变化判断。

浏览器在哪台机器运行不决定路径语义。后端运行在 WSL 时应填写 WSL 路径，
例如 `./crispasr/models`；Windows 浏览器的本地磁盘路径不能直接作为 Linux
服务路径。使用 WSL 挂载路径时，
部署者还需先将对应根目录加入允许范围，并保证 WSL 服务用户有访问权限。

## API 契约

路径管理接口位于 `/api/v1/settings/local-asr`，仅暴露这两个允许管理的字段及其
状态；同前缀的只读 `/models` 接口提供当前生效目录的模型发现结果。
不提供完整 YAML、任意文件读取/写入或密钥查询。

### GET `/api/v1/settings/local-asr`

响应包含：

| 字段 | 含义 |
| --- | --- |
| `crispasr_executable`、`crispasr_model_dir` | 隐私表示的路径；普通字段为保存值，环境变量管理字段显示当前环境值 |
| `active` | 当前后端进程实际使用的同名两字段，使用相同隐私表示 |
| `managed_by_environment` | 同名两字段的布尔标记 |
| `restart_required` | 保存后的有效配置是否与当前进程不同 |
| `editable` | 当前配置是否可通过设置接口保存 |
| `allowed_roots` | 服务端允许的根目录，以 `./...` 或 `@root/N` 表示 |
| `revision` | 保存时必须原样传回的不透明版本标识 |

### PUT `/api/v1/settings/local-asr`

请求包含两个字符串字段和最近一次读取的 `revision`：

```json
{
  "crispasr_executable": "./crispasr/linux-v0.8.38/crispasr-linux-x86_64-cuda13/crispasr",
  "crispasr_model_dir": "./crispasr/models",
  "revision": "<GET 返回的版本标识>"
}
```

保存重新验证字段及路径后，原子更新 YAML 中的两个允许键。
响应返回更新后的设置状态。版本不一致返回标准错误响应，HTTP `409`，
错误码 `SETTINGS_REVISION_CONFLICT`，避免多个页面或外部配置修改互相覆盖。
发生冲突后重新读取、核对最新值再保存，不自动覆盖新的配置。

### POST `/api/v1/settings/local-asr/check`

请求仅包含 `crispasr_executable` 和 `crispasr_model_dir` 两个字符串，
不需要 `revision`。响应结构为：

```json
{
  "executable": {"ok": true, "message": "<检查说明>", "version": "0.8.38"},
  "model_dir": {"ok": true, "message": "<检查说明>"}
}
```

版本无法确认时 `version` 为 `null`。可执行文件检查采用固定 `--version` 命令
和参数列表，不经过 shell；模型目录检查确认
路径允许且目录可读。检查不保存、不下载模型、不执行推理。
目录检查通过不证明其中存在兼容模型，也不证明 GPU、模型加载或完整 ASR 推理就绪。
真实识别仍须在项目中手动选择模型与语言并运行短音频验证。

## 本地管理边界

接口仅接受直接连接的 loopback 客户端和 loopback `Host`。请求如有 `Origin`，
其协议、主机和端口必须与请求同源。设置接口拒绝携带 `Forwarded` 或任何
`X-Forwarded-*` 头的请求，转发管理访问不受支持；拒绝时返回
`SETTINGS_LOCAL_ONLY`。本地代理必须保留 loopback `Host` 和同源 `Origin`，
且不添加转发头（当前 Vite 默认代理符合此要求）。网络代理或远程浏览器连接可能
被拒绝，不要通过伪造转发头绕过本地管理限制。

客户端只能选择服务端管理员允许的路径。`app.crispasr_allowed_roots` 是 YAML
列表，默认包含配置根目录下的 `./crispasr`；进程启动时已配置的可执行文件父目录
及模型目录也作为初始允许范围。扩展允许范围只能由部署者手动编辑服务端 YAML，
设置 API 不允许修改根目录列表。

路径校验拒绝遍历片段、控制字符、NUL 和符号链接逃出允许根目录。
可执行文件必须是名为 `crispasr`（适用平台可为 `crispasr.exe`）的普通可执行文件；
模型路径必须是可读目录。选择范围外的目录时，先由部署者调整允许根目录，再重启
后端；不能把路径限制当成任意命令或任意文件管理入口。

## 部署者排查

- **无法保存：** 确认后端实际加载的 `VOICETRANSL_CONFIG`、文件与父目录写权限，
  并检查字段是否受环境变量管理。
- **路径被拒绝：** 确认使用的是后端操作系统路径，目录在允许根目录内，且没有
  遍历片段或符号链接逃逸。额外根目录由部署者在 YAML 中配置。
- **检查失败：** 确认可执行文件名称与执行权限、版本命令可运行以及模型目录可读。
- **保存后仍使用旧路径：** 查看 `active` 和 `restart_required`，在合适时机手动
  重启后端；如仍不符，核对环境变量覆盖和实际加载的配置文件。
- **检查成功但任务失败：** 按 [CrispASR Provider](crispasr_provider.md) 检查模型文件、
  CLI 功能、后端及语言参数，使用短音频验证实际推理。
