# VoiceTransl v0.2 前端工作流设计

> 文档状态：设计基线
>
> 适用版本：v0.2
>
> 目标：一个项目包含多个音频资源；选择一个、多个或全部音频，配置流程后启动。资源、目录与 API 契约以 [多音频项目契约](voicetransl_multi_audio_project.md) 为准，取代 v0.1 的单音频资源粒度及此前“每文件创建独立项目”的设计。

### 当前实现状态

当前实现与验收以多音频项目为准：多文件选择、拖放与上传队列的首个成功文件创建父项目，后续文件添加到同一项目。显示有效/已选、已上传、待完成和失败数量；队列保留父项目 ID 和各音频 ID。失败项可独立重试，不重新创建成功资源；父项目尚未创建时重试创建，已有父项目时重试添加音频。队列保存在页面会话内，刷新后通过项目列表和音频列表访问已保存资源。此前每文件创建独立项目的行为已被替代，历史独立项目不自动合并。

上传期间锁定队列和基础资料，阻止应用内离开，并通过浏览器离开提示保护未完成上传。项目名只填写一次，用于整组音频；各音频保留原始文件名。重复选择同一个文件时明确提示并跳过；不同的同名文件给出提示后保存为独立音频资源，不覆盖。

前端通过 `GET /api/v1/upload-policy` 读取当前后端允许的扩展名和大小限制；获取失败时可重试，规则未取得前不提交。MIME 类型和原始文件名在后端保留为资料：当前后端不限制 MIME、空文件或原始文件名字符，源路径由项目 ID 和扩展名生成，前端不另设更严格的字符/MIME规则，也不宣称完成真实音频内容校验。

创建后不会自动运行 Pipeline。在项目工作台选择一个、多个或全部音频，配置并检查流程，将配置应用到所选音频后启动。项目有公共默认配置，各音频可独立覆盖；每个音频拥有自己的任务、进度、字幕和输出。

顶部服务状态旁始终提供“设置”，从任意视图打开应用级模态框，检查或保存后端
CrispASR 可执行文件与模型目录。保存后需手动重启后端生效，当前进程和运行/排队
任务保持原设置；受环境变量管理的字段只读。详见
[全局本地 ASR 设置](voicetransl_global_settings.md)。ASR 配置弹窗支持当前生效
目录的本地模型发现与刷新，显式选择文件后匹配 backend；源语言仍手动选择。
目录检查与模型发现均不代表推理就绪。

## 1. 设计目标

v0.1 的前端主要用于观察 Mock Pipeline 的处理进度。v0.2 开始接入真实预处理、ASR、对齐和翻译 Provider 后，用户需要在任务启动前明确处理配置。

v0.2 前端应满足以下目标：

- 用户可以先配置各阶段的 Provider、模型和处理参数，再启动任务。
- 配置经过校验后才允许开始处理。
- 任务启动时保存不可变的配置快照，运行中的任务不受后续配置修改影响。
- 多个音频可以一次上传到同一项目，并选择一个、多个或全部应用配置后启动。
- 每个音频有独立任务、进度、字幕和输出，单个文件失败不影响其他文件。
- 保留 v0.1 的 Pipeline 工作台，用于展示运行状态、阶段详情和输出文件。

## 2. 非目标

v0.2 暂不实现以下能力：

- 拼接多个音频源文件或合并字幕输出。
- 跨音频联合翻译上下文（当前共同处理仅指共享流程配置）。
- 跨多个音频的统一时间轴。
- 多用户协作、权限管理和账号系统。
- 运行中的任务动态切换模型。
- 多轨音频混音或声道级项目管理。

## 3. 用户主流程

```text
项目列表
  ↓
新建项目 / 向已有项目添加音频
  ↓
选择音频并填写基础信息
  ↓
进入项目工作台，选择一个 / 多个 / 全部音频，配置 Pipeline
  ↓
检查配置摘要
  ↓
应用配置到所选音频并开始处理
  ↓
Pipeline 工作台
```

单文件和多文件上传使用同一条流程，均创建一个项目。已有项目也可添加音频；焦点音频决定查看的 Pipeline、字幕和输出，勾选范围决定配置应用与启动对象。

## 4. 页面与视图

### 4.0 全局设置

“设置”入口与顶部服务指示器并列，不依赖项目或焦点音频。模态框只编辑全局本地
ASR 的两项路径，展示设置值、当前实际生效值、环境变量只读原因和重启提示。
普通字段显示保存值，环境变量管理字段显示当前环境值，不展示或覆盖其底层 YAML 值。
路径显示为配置根目录内的 `./...` 或外部授权根目录别名 `@root/N[/suffix]`，
避免展示私人绝对目录；显示表示不改变真实运行路径或允许选择的范围。
检查使用草稿且不保存；保存时携带配置版本，冲突后提示重新读取，不覆盖他人修改。
打开或关闭设置保留当前页面、上传队列和 WebSocket；未保存修改关闭前确认丢弃，
并提供键盘操作、焦点约束和焦点恢复。设置失败不取消项目任务。

### 4.1 项目列表

项目列表继续作为入口，每个项目显示：

- 项目名称和音频数量
- 音频资料和源语言
- 各音频任务状态的数量摘要
- 各音频独立进度与当前阶段
- 最近更新时间

多文件上传后列表只出现一个项目，进入项目后显示音频资源列表。不得把某一个音频的进度误写成全项目进度。

### 4.2 新建项目：文件选择

上传区域需要支持单文件和多文件：

- 原生文件选择器使用 `multiple`。
- 拖放区域支持一次拖入多个音频。
- 仅接受配置允许的音频格式。
- 每个文件显示文件名、大小、校验状态和移除按钮。
- 文件名冲突时给出明确提示，不静默覆盖。
- 单个文件校验失败时，不影响其他文件继续配置。

示例：

```text
待处理文件（3）

episode-01.wav   128 MB   ✓
episode-02.wav    96 MB   ✓
episode-03.mp3    42 MB   ✓

[移除失败文件] [上传到项目]
```

文件校验遵循后端上传策略的扩展名与大小限制；MIME 和原始文件名作为资料保存，内部安全路径由后端生成。真实音频时长可在预处理阶段读取，不要求浏览器上传前完整解析。

### 4.3 Pipeline 配置

仅保留“处理进度”五阶段节点作为导航，不另设 CONFIGURATION MAP 或重复的五节点配置总览。
点击节点只切换下方的阶段专属工作区，不打开配置弹窗。工作区展示阶段状态和真实结果，
独立的“配置此阶段”按钮打开该节点专属模态框：

```text
预处理 ✓ ── 语音识别 ⚠ ── 时间轴对齐 ✓ ── 翻译 未配置 ── 导出 ✓
```

节点状态至少包括“未配置、已配置、有错误、处理中、已完成”。配置模态框支持
保存、取消和未保存修改提示；任务运行、取消或排队时该音频字段只读但允许查看。
配置尚未加载时入口禁用并说明原因。工作区明确区分“本次任务快照”和“下次处理配置”；
没有任务快照时标记尚未开始，不把可编辑配置冒充实际使用模型。项目公共默认
配置用于新加入音频，各音频可独立覆盖。应用配置时明确显示选择范围与数量，
未选音频不变；查看的焦点音频与勾选的操作范围分开。

#### 预处理

- Provider：`mock`（默认演示）或 `ffmpeg`（真实音频）
- 目标采样率
- 声道数
- 是否保留原始音频

选择 `ffmpeg` 时，后端使用参数列表调用 FFmpeg，将源文件转换到当前音频目录内的
`cache/preprocessed.wav`，并写入 `cache/preprocess.json`。原始上传文件始终保留，
`preserve_original` 会记录在预处理元数据和任务配置快照中，不允许预处理阶段覆盖源文件。
FFmpeg 不可用、转换失败或没有生成输出文件时，任务会以稳定的预处理错误码失败。

#### 语音识别

- Provider
- 模型
- 源语言
- VAD 和分段策略
- 长音频处理策略

选择 `crispasr` 时，ASR 弹窗打开后读取一次当前后端已生效目录的模型列表，并提供
显式刷新入口；运行或排队时可查看和刷新，但字段及模型选择只读。保存全局
目录后尚未重启时，仍显示原目录及重启提示。未知、损坏或不兼容项禁用并说明原因。
用户显式选择可用文件才更新草稿中的模型名及匹配 backend，不自动选首项、不自动
保存、不改语言；旧配置或手动模型输入保持可用。支持 `qwen3`（通用 0.6B），
保留既有 `qwen3-1.7b` 参数。接口、能力边界详见
[CrispASR 模型发现](crispasr_provider.md#local-model-discovery)。

#### 时间轴对齐

- 是否启用
- 对齐 Provider
- 对齐模型
- 无时间轴输入时的处理方式

#### 翻译

- Provider
- 模型
- OpenAI-compatible Chat Completions、OpenAI Responses 或 Anthropic Messages 协议
- 服务基础地址
- API Key 环境变量名（只填写名称，不填写密钥）
- 目标语言
- 批量大小
- 温度、请求超时
- 术语表和翻译提示词

#### 导出

- SRT
- VTT
- LRC
- 中文字幕或双语字幕
- 输出文件命名规则

Provider 地址和 API Key 环境变量名会随项目配置保存；真实 API Key 只由后端从
环境变量读取，前端和项目文件都不能保存密钥值。

### 4.4 配置摘要与启动

开始处理前显示只读摘要：

```text
项目：ASMR 第一期
应用范围：episode-01.wav、episode-02.wav（已选 2 / 3）
源语言：日语
目标语言：中文
ASR：CrispASR / default
对齐：启用
翻译：OpenAI-compatible / xxx-model
导出：中文 SRT、双语 SRT、VTT

[保存配置] [应用到所选并开始]
```

启动按钮只有在以下条件全部满足时才可用：

- 至少有一个通过校验的音频文件。
- 所有必需阶段都有可用 Provider。
- 源语言和目标语言有效且不冲突。
- 参数通过前端基础校验。
- 后端配置检查成功。

界面必须明确显示将要处理的音频与数量。先保存所选音频配置，再启动；配置保存失败的音频不得以旧配置意外启动。继续失败、取消或中断任务时保留旧快照，不因应用新配置改变正在恢复的任务。批量结果逐项显示，重试不能重复启动成功项。

### 4.5 Pipeline 工作台

任务启动后沿用 v0.1 的工作台：

- 顶部显示项目名称、音频列表与选择范围，每项有独立状态和进度。
- 中部显示当前焦点音频的五阶段 Pipeline。
- 点击节点只选择阶段，下方保持一个阶段专属工作区；配置从该工作区的独立按钮进入。
- 工作区显示进度、开始/结束时间、错误与阶段状态说明、任务 Provider/模型快照和下次配置摘要。
- 预处理显示源音频资料和实际预处理元数据（采样率、声道等）；不绘制伪造的波形。
- 语音识别显示原始识别文本与时间；时间轴对齐显示对齐后的片段时间；翻译显示源文与译文对照。
- 导出工作区显示各输出文件的独立下载入口，不在公共底部重复输出列表。
- 详情按当前音频、当前任务和所选阶段读取；切换或重新处理后丢弃旧响应。REST 和 WebSocket 更新当前阶段结果，不轮询所有阶段。
- 明确显示加载、失败、未完成、跳过和缺失产物状态，缺失产物可刷新详情或重新处理。

运行中的配置只读。用户可以使用“复制配置并重新运行”创建新任务，而不是修改当前任务。

## 5. 状态模型

前端需要区分配置状态和任务状态。

### 5.1 配置状态

```text
draft       尚未完成配置
valid       配置校验通过，可启动
invalid     配置存在错误
submitted   已应用到所选音频
```

### 5.2 任务状态

继续使用 v0.1 的任务状态：

```text
pending → running → completed
                 ├→ failed
                 ├→ cancelled
                 └→ interrupted
```

每个音频拥有独立任务状态；项目视图只额外显示汇总信息，例如 `2/3 已完成，1 个失败`。上传状态与任务状态分开。

### 5.3 项目删除与重新处理

项目可以从项目列表或详情页删除。删除前必须二次确认，并明确提示会移除整组源音频、字幕和输出；任一音频运行、取消中或排队时返回 `PROJECT_BUSY`，需要先结束相应任务。所有音频均不忙碌时才可删除。

音频处理完成后可以点击“重新处理”。这会为该音频创建新的 Job ID，并使用当前可编辑配置生成新的 `job.config_snapshot`；旧任务不会被当作新任务继续恢复。失败、取消和中断任务仍可按原配置快照继续处理。不同音频可独立排队，遵守全局并发限制。

## 6. 配置快照

点击“开始处理”时，后端必须将最终配置写入当前任务的 `job.config_snapshot`。配置快照满足：

- 包含每个阶段实际选用的 Provider、模型和非敏感参数。
- 不包含 API Key 等敏感凭据。
- 任务运行期间不可变。
- 失败后继续运行时继续使用同一快照。
- 重新运行时生成新的任务和新的快照。

前端展示的阶段详情应以任务快照为准，而不是以当前全局配置为准。

## 7. 同项目多音频语义

v0.2 的多个音频采用“一个项目包含多个音频资源”的语义：

- 一个文件对应项目内一个音频资源。
- 每个音频对应自己的 `job.json`、字幕与输出目录。
- 项目保存公共默认配置，可将一套配置应用到选中的一个、多个或全部音频。
- 一个文件失败不会自动取消其他文件。
- 上传队列保留一个父项目 ID，以及每个文件的音频 ID 和上传结果。
- 上传失败的文件可在同项目单独重试，不重复创建成功资源。

首个文件使用项目创建接口，后续文件使用该项目的音频添加接口。音频列表与独立配置、启动、取消、字幕、输出接口见多音频项目契约。共享流程不合并时间轴，不自动合并历史项目。

## 8. 错误与恢复

错误提示需要说明原因和下一步操作：

- Provider 不可用：提示检查后端 Provider 配置。
- 文件格式不支持：提示支持的格式。
- 文件过大：提示限制和解决办法。
- 单个音频上传或启动失败：在同项目单独重试，展示逐项结果。
- 任务运行失败：定位到失败阶段，并提供继续或复制配置重新运行。
- 后端服务不可用：提示启动服务或稍后重试，不显示原始 500 文本作为唯一信息。

## 9. 与 v0.1 的兼容要求

- 保留现有 Project、Job、Transcript、Output 资源结构。
- 保留 REST 作为真实状态来源，WebSocket 只负责实时通知。
- 保留 `mock` preset，不能让真实模型依赖成为前端测试前提。
- 并发保护粒度改为单音频单任务，不同音频使用全局并发限制。
- 保留各音频独立时间轴，项目仅组织音频并共享默认配置。
- 旧项目作为含一个 `aud_primary` 音频的项目直接打开，旧接口指向该音频。

## 10. v0.2 前端验收标准

- 可以选择一个或多个音频文件。
- 可以移除单个文件，并正确显示文件校验错误。
- 可以配置每个 Pipeline 阶段的 Provider、模型和处理参数。
- 配置无效时无法开始处理，并能定位具体错误。
- 开始处理前能看到完整配置摘要。
- 开始处理后任务使用固定配置快照。
- 多文件上传只创建一个项目和多个音频，已有项目可添加音频。
- 可以选择一个、多个、全部音频应用配置并启动，未选音频配置不变。
- 一个音频失败时，其他音频仍可继续处理，各自字幕与输出互不覆盖。
- 任一音频忙碌时项目删除被拒绝，同音频重复启动被拒绝。
- Pipeline 工作台能展示实际 Provider、模型和阶段状态。
- 五个进度节点只切换阶段内容，不打开弹窗；没有重复的节点配置总览。
- 每个阶段的独立配置入口打开正确模态框，保存、取消、未保存提示及运行/排队只读正常。
- 完成任务的识别、对齐和翻译各读取自己的阶段产物，不以最新翻译覆盖原始识别结果。
- 快速切换节点、音频或重新处理时，延迟响应不能覆盖当前阶段；输出仅在导出阶段显示。
- Mock preset 的既有测试和流程继续通过。
- 项目列表、上传页和项目工作台均可打开全局设置，检查不保存，保存后明确提示
  手动重启；环境变量管理字段只读，版本冲突不覆盖最新配置。
- 全局设置操作保留当前视图、上传队列和 WebSocket，未保存关闭提示与键盘焦点管理正常。
- CrispASR 模型发现可刷新，显式选文件匹配 backend；不覆盖旧/手动模型、不自动
  保存或改变源语言，禁用项及重启待生效状态有明确说明。

## 11. 推荐实现顺序

1. 先实现单文件配置页和配置摘要。
2. 增加 `job.config_snapshot` 的后端持久化和展示。
3. 接入真实预处理 Provider，并保留 Mock fallback。
