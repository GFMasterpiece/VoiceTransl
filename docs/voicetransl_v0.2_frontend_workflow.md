# VoiceTransl v0.2 前端工作流设计

> 文档状态：设计基线
>
> 适用版本：v0.2
>
> 目标：在保留 v0.1 Pipeline 资源模型的基础上，增加“先配置、后执行”的真实处理工作流，并支持多个音频的批量上传。

## 1. 设计目标

v0.1 的前端主要用于观察 Mock Pipeline 的处理进度。v0.2 开始接入真实预处理、ASR、对齐和翻译 Provider 后，用户需要在任务启动前明确处理配置。

v0.2 前端应满足以下目标：

- 用户可以先配置各阶段的 Provider、模型和处理参数，再启动任务。
- 配置经过校验后才允许开始处理。
- 任务启动时保存不可变的配置快照，运行中的任务不受后续配置修改影响。
- 多个音频可以一次上传，并共享一套配置批量创建项目。
- 每个音频仍然是独立项目和独立任务，单个文件失败不影响其他文件。
- 保留 v0.1 的 Pipeline 工作台，用于展示运行状态、阶段详情和输出文件。

## 2. 非目标

v0.2 暂不实现以下能力：

- 将多个音频合并成一个项目。
- 跨多个音频的统一时间轴。
- 多用户协作、权限管理和账号系统。
- 运行中的任务动态切换模型。
- 多轨音频混音或声道级项目管理。

## 3. 用户主流程

```text
项目列表
  ↓
新建项目 / 批量上传
  ↓
选择音频并填写基础信息
  ↓
配置 Pipeline
  ↓
检查配置摘要
  ↓
保存配置并开始处理
  ↓
Pipeline 工作台
```

单文件和多文件上传使用同一条流程。多文件场景只在“选择音频”和“创建项目”阶段增加批量行为。

## 4. 页面与视图

### 4.1 项目列表

项目列表继续作为入口，每个项目显示：

- 项目名称和源文件名
- 文件大小和源语言
- 当前任务状态
- 总进度
- 当前处理阶段
- 最近更新时间

批量创建后，列表中出现多个独立项目。列表不显示“合并项目”概念。

### 4.2 新建项目：文件选择

上传区域需要支持单文件和多文件：

- 原生文件选择器使用 `multiple`。
- 拖放区域支持一次拖入多个音频。
- 仅接受配置允许的音频格式。
- 每个文件显示文件名、大小、校验状态和移除按钮。
- 文件名冲突时给出明确提示，不静默覆盖。
- 单个文件校验失败时，不影响其他文件继续配置。

示例：

```text
待处理文件（3）

episode-01.wav   128 MB   ✓
episode-02.wav    96 MB   ✓
episode-03.mp3    42 MB   ✓

[移除失败文件] [继续配置]
```

文件校验至少包括：扩展名、MIME 类型、文件大小、文件名可安全存储性。真实音频时长可在后端预处理阶段读取，不要求浏览器在上传前完成完整解析。

### 4.3 Pipeline 配置

配置页按阶段分组，不直接把所有高级参数堆在同一层：

```text
Pipeline 配置
├── 预处理
├── 语音识别
├── 时间轴对齐
├── 翻译
└── 导出
```

每个阶段支持“快速预设”和“高级设置”。快速预设用于常用场景，高级设置按需展开。

#### 预处理

- Provider：`mock`（默认演示）或 `ffmpeg`（真实音频）
- 目标采样率
- 声道数
- 是否保留原始音频

选择 `ffmpeg` 时，后端使用参数列表调用 FFmpeg，将源文件转换到项目内的
`cache/preprocessed.wav`，并写入 `cache/preprocess.json`。原始上传文件始终保留，
`preserve_original` 会记录在预处理元数据和任务配置快照中，不允许预处理阶段覆盖源文件。
FFmpeg 不可用、转换失败或没有生成输出文件时，任务会以稳定的预处理错误码失败。

#### 语音识别

- Provider
- 模型
- 源语言
- VAD 和分段策略
- 长音频处理策略

#### 时间轴对齐

- 是否启用
- 对齐 Provider
- 对齐模型
- 无时间轴输入时的处理方式

#### 翻译

- Provider
- 模型
- 目标语言
- 批量大小
- 温度或等效随机性参数
- 术语表和翻译提示词

#### 导出

- SRT
- VTT
- LRC
- 中文字幕或双语字幕
- 输出文件命名规则

Provider 地址、API Key 和其他敏感凭据只保存在后端配置中。前端只显示可用 Provider 和模型选项，不直接保存密钥。

### 4.4 配置摘要与启动

开始处理前显示只读摘要：

```text
文件：3 个
源语言：日语
目标语言：中文
ASR：CrispASR / default
对齐：启用
翻译：OpenAI-compatible / xxx-model
导出：中文 SRT、双语 SRT、VTT

[保存配置] [开始处理]
```

启动按钮只有在以下条件全部满足时才可用：

- 至少有一个通过校验的音频文件。
- 所有必需阶段都有可用 Provider。
- 源语言和目标语言有效且不冲突。
- 参数通过前端基础校验。
- 后端配置检查成功。

如果批量文件中只有部分文件有效，界面必须明确显示将要创建的文件数量，不能让用户误以为所有文件都会处理。

### 4.5 Pipeline 工作台

任务启动后沿用 v0.1 的工作台：

- 顶部显示项目状态和总进度。
- 中部显示五阶段 Pipeline。
- 点击节点查看阶段详情、实际使用的 Provider/模型和处理日志。
- 右侧显示字幕预览。
- 底部显示输出文件。

运行中的配置只读。用户可以使用“复制配置并重新运行”创建新任务，而不是修改当前任务。

## 5. 状态模型

前端需要区分配置状态和任务状态。

### 5.1 配置状态

```text
draft       尚未完成配置
valid       配置校验通过，可启动
invalid     配置存在错误
submitted   已提交创建项目
```

### 5.2 任务状态

继续使用 v0.1 的任务状态：

```text
pending → running → completed
                 ├→ failed
                 ├→ cancelled
                 └→ interrupted
```

批量上传时，每个文件拥有独立任务状态；批量视图只额外显示汇总信息，例如 `2/3 已完成，1 个失败`。

### 5.3 项目保留与完成态

项目创建后永久保留，v0.2 不提供项目删除接口或删除按钮。处理完成是终态：已完成项目可以查看字幕和输出文件，但不能再次启动处理，也不能修改处理配置。后端对 `resume=true` 和 `resume=false` 都返回 HTTP 409、错误码 `JOB_ALREADY_COMPLETED`。失败、取消和中断任务仍可按原配置快照继续处理。

## 6. 配置快照

点击“开始处理”时，后端必须将最终配置写入当前任务的 `job.config_snapshot`。配置快照满足：

- 包含每个阶段实际选用的 Provider、模型和非敏感参数。
- 不包含 API Key 等敏感凭据。
- 任务运行期间不可变。
- 失败后继续运行时继续使用同一快照。
- 重新运行时生成新的任务和新的快照。

前端展示的阶段详情应以任务快照为准，而不是以当前全局配置为准。

## 7. 批量上传语义

v0.2 的多个音频采用“批量创建多个独立项目”的语义：

- 一个文件对应一个项目。
- 一个项目对应一个 `job.json` 和一组输出文件。
- 所有文件可以共享同一套 Pipeline 配置。
- 一个文件失败不会自动取消其他文件。
- 批量创建返回每个文件的项目 ID 和创建结果。
- 创建失败的文件可以单独重试，不重复创建已经成功的项目。

推荐的后端演进方式是先复用现有单文件创建接口，由前端逐个提交并显示创建进度；等批量场景稳定后，再增加原子性更明确的批量 API。

## 8. 错误与恢复

错误提示需要说明原因和下一步操作：

- Provider 不可用：提示检查后端 Provider 配置。
- 文件格式不支持：提示支持的格式。
- 文件过大：提示限制和解决办法。
- 单个批量项目创建失败：允许单独重试。
- 任务运行失败：定位到失败阶段，并提供继续或复制配置重新运行。
- 后端服务不可用：提示启动服务或稍后重试，不显示原始 500 文本作为唯一信息。

## 9. 与 v0.1 的兼容要求

- 保留现有 Project、Job、Transcript、Output 资源结构。
- 保留 REST 作为真实状态来源，WebSocket 只负责实时通知。
- 保留 `mock` preset，不能让真实模型依赖成为前端测试前提。
- 保留单项目单任务约束。
- 不因为批量上传引入“多音频合并项目”。
- 旧项目仍然可以直接打开 Pipeline 工作台。

## 10. v0.2 前端验收标准

- 可以选择一个或多个音频文件。
- 可以移除单个文件，并正确显示文件校验错误。
- 可以配置每个 Pipeline 阶段的 Provider、模型和处理参数。
- 配置无效时无法开始处理，并能定位具体错误。
- 开始处理前能看到完整配置摘要。
- 开始处理后任务使用固定配置快照。
- 批量上传会创建多个独立项目。
- 一个批量项目失败时，其他项目仍可继续处理。
- Pipeline 工作台能展示实际 Provider、模型和阶段状态。
- Mock preset 的既有测试和流程继续通过。

## 11. 推荐实现顺序

1. 先实现单文件配置页和配置摘要。
2. 增加 `job.config_snapshot` 的后端持久化和展示。
3. 接入真实预处理 Provider，并保留 Mock fallback。
4. 将文件选择器扩展为多文件，先由前端逐个创建项目。
5. 增加批量创建进度、部分失败和单项重试。
6. 再接入真实 ASR、对齐和翻译 Provider。
7. 最后补字幕编辑和高级批处理能力。

每完成一个独立阶段，都应保留一个最小可运行 commit，并运行前后端测试；未经验证不推进下一阶段。
