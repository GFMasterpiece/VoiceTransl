# 仅保留节点独立连接

> 节点职责、字段位置及版本边界已由[可组合配置规格](composable-node-configuration.md)取代。下文保留该里程碑的协议/行为与早期验收记录；旧内嵌图和旧目录不再作为当前执行契约，现用配置见[节点连接](../docs/node_connections.md)。

状态：**Implemented**（2026-11-08）。用户明确要求移除旧服务连接兼容；本规格取代先前关于 Profile、连接模式及环境变量备用路径的兼容要求。

## 范围与影响

- Filetrans 与 Streaming 均只使用自身节点的地址、超时、可选地域及不可变凭据引用；密钥在节点内输入，通过既有只写更新存入独立加密存储。
- 删除全局服务连接界面、Profile store、CRUD API、存储读写/引用检查、目录选项派生、Profile 冻结及环境变量密钥解析。不再读取 `provider_profiles.json`，该文件即使损坏也不影响目录或运行。
- 删除 Filetrans 的 `provider_profile_id`、`connection_mode`、`api_key_env` 字段，不为旧图补默认连接、不自动迁移、不改读其他节点的密钥。
- 含上述旧字段的节点在保存、启动及重试时明确拒绝，用户删除后重新添加云节点并填写本节点的连接/密钥；这也适用于之前带这些兼容字段的内联 Filetrans 节点。
- 当前 Streaming 节点的地址、模型、凭据、输入范围及协议保持原行为。

## 数据与历史

- 持久化 schema 保持 `1.0`；不删除或批量改写项目、公共图、修订、运行、批次、凭据密文或产物。
- 历史 `provider_profiles_snapshot` 只作为原始元数据被动读取，不保留专用 Profile 解析器，不参与当前执行、重试、鉴权或目标推断。新图提交不生成该字段；复制历史快照仍可保留原始元数据。
- 历史产物继续按原归属和路径安全规则查看/下载；旧连接不会因为展示历史而恢复。
- 其他旧 Pipeline 的只读配置和独立留存的翻译适配器不在本轮删除范围，不能据其中的字段恢复服务连接入口。

## 目录与执行

- 能力目录升为 `1.11`，持久化版本不变。
- 保留 `presentation.inline_connection_input` 名称，字段仅为 `provider_type`、`label`、`base_url_key`、`timeout_key`、可空 `region_key`、`credential_ref_key` 及可选 `data_handling`；不再发布/接受 Profile 声明、模式或环境变量角色。
- 前端根据目录装配连接表单，不维护节点类型名单。此前目录中的旧服务连接声明明确拒绝，与连接无关的旧目录语义继续保留。
- 通用连接模块只冻结、验证和读取节点自身的连接及凭据版本；Filetrans 适配器必需显式连接和 Key，Streaming 保持显式路径。缺 Key 不读环境变量、不发起网络请求。
- 同项目不同节点、不同协议或不同项目不能互用凭据引用。复制和导入导出仍剥离引用，不复制私有密码缓冲。
- 批次及重试继续使用原图和原凭据版本；不采用后来修改的节点设置，不恢复已退役的连接机制。

## 验收

- Filetrans 与 Streaming 单/批运行、输出、取消、超时及认证隔离继续通过；同图多实例使用各自地址/密钥。
- 服务连接入口与 CRUD 不存在，目录没有旧字段/角色，修改或破坏旧 Profile 文件不影响目录。
- 环境变量有值而节点没有密钥时，保存草稿允许、运行拒绝且无网络请求；含旧字段的图和重试明确失败。
- 旧项目、运行及产物仍可被动读取，原始文件字节不变；新运行不生成旧 Profile 快照。
- 私有密码、幂等保存、复制剥离、不可变队列/重试及跨节点引用检查继续覆盖。
- 后端全量/Ruff、前端全量/构建与 Windows 隔离模拟平台浏览器验收；不使用真实凭据、用户音频或付费接口。

## 实际验证

- Windows 后端全量 **614 passed, 4 skipped**，Ruff 检查和格式检查通过。Filetrans 协议定向 **83 passed**；连接/凭据/Streaming 交叉回归 **48 passed**。旧字段六种取值覆盖保存、单运行、批次创建及重试的明确拒绝，旧 Profile 文件损坏不影响目录。四项跳过不视为通过。
- 前端全量 **435 passed**、构建通过；实际后端 1.11 目录可解析。旧 CRUD/兼容测试已删除或改写，现有密钥安全、幂等保存、草稿保护、复制剥离和旧历史提示继续覆盖。
- Headless Edge + 隔离假 HTTP/WebSocket：两种云节点分别配置自己的 Key，双文件批次、普通运行、提交后轮换仍沿冻结地址/Key、真实字幕时间、取消及连接回收通过；旧 CRUD 的 GET/POST/PUT/DELETE 均为 404，网页无入口或旧 API 请求。环境变量有值而 Filetrans 缺 Key 时明确拒绝，旧字段保存拒绝且不改修订。
- 浏览器补验旧图显示重建提示且不能运行，删除后重新添加节点可正常保存、无旧字段和凭据继承。旧历史同时含实际 Profile 地址与闲置 inline 地址时，均不解释为节点目标；原产物仍可下载，读取前后历史文件字节一致。两轮浏览器异常为 0。
- 仅使用合成 WAV、假 Key 和临时数据，不修改用户服务或数据，未调用付费平台；其他系统、真实质量与计费未实测。
