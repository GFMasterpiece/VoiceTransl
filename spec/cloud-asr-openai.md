# OpenAI 云端 ASR

> 状态：Draft（接入方向已进入线路图；接口细节及用户体验决策尚未批准）

## 目标

在现有 ASR 阶段增加首个云端 Provider，将服务端识别结果转换为统一 `Transcript`，继续复用后续对齐、翻译和导出流程。音频只在用户明确选择云端处理后发送到所选服务商；前端不直接调用服务商。

当前 ASR runtime 仅支持 Mock 和本地 CrispASR。Provider Profile 的后端存储、CRUD、引用校验和非密钥任务快照已经存在，但还没有密钥解析、OpenAI ASR HTTP 请求、ASR runtime dispatch 或 Profile 管理 UI。当前能力见 [`../docs/provider_profiles.md`](../docs/provider_profiles.md)。

## 首版范围建议

- 只接入 OpenAI Speech-to-Text，不同时引入其他云端 Provider。
- 作为现有 ASR Provider 实现，不新增 Pipeline 阶段。
- 服务端从 Provider Profile 的 `api_key_env` 对应环境变量读取 API Key；密钥不得进入 Profile 文件、项目配置、Job 快照、接口响应或日志。
- 校验服务端响应并转换为领域 `Transcript`；不能把原始服务商响应作为前端产物。
- 覆盖超时、取消、鉴权/配额错误、无效响应和可重试服务错误，并以稳定错误展示；失败不能静默回退至 Mock。
- 在运行前明确提示目标服务商/区域及音频外发行为。

此范围仍是建议，获批后才能作为冻结要求。

## 安全与兼容要求

- 新建项目继续默认 Mock；旧项目和 Job 快照保持可读，不因新增 Provider 自动迁移或修改。
- 新任务保存非密钥 Profile 快照；恢复任务沿用原快照，不能悄悄使用后来修改的 Profile。
- 单元测试使用 fake HTTP，不依赖真实凭据或用户音频；真实调用必须作为显式冒烟验证。
- 只发送当前任务所需音频，并告知用户服务商的数据保留取决于服务商政策，应用不能保证远端删除。

## 待决策和官方信息核验

- 使用 OpenAI 官方 API，还是兼容 OpenAI 协议的服务也纳入首版？
- 首版选哪些模型和返回格式？它们分别支持什么语言、时间戳粒度和最大文件限制？
- 超过当前服务限制时，首版拒绝还是做静音感知分块？不能截断后声称完整识别。
- 无可靠片段时间戳的结果如何进入当前 Mock/fallback 对齐阶段？
- 超时、重试次数、退避、错误码和可恢复性如何定义？
- 音频外发提示是每次启动确认，还是用户在 Profile/项目中显式授权后记住？
- 临时音频副本保存在哪里、何时清理，用户/部署者可配置什么区域？

实现前必须重新核对 OpenAI 官方 Speech-to-text 文档中的模型、接口字段、时间戳能力和文件限制；易变的服务商限制不能作为永久常量未经验证写入代码或文档。

## 初步验收

1. 成功响应被正确映射为有效 `Transcript`；无效响应、空结果和非法时间戳不会被误报成功。
2. fake HTTP 测试覆盖鉴权失败、配额/输入错误、服务端错误、超时和取消。
3. 密钥不出现在响应、持久文件、Job 快照、错误详情和日志中。
4. 音频未超出明确的服务端限制才可提交；超限策略按批准的决定执行。
5. 多音频任务独立失败/完成，恢复任务使用原始快照。
6. 前端在启动前清楚提示音频外发对象，后端未接通时不能展示为可运行能力。

完成并验收后，将实际 API/部署说明写入 `docs/provider_profiles.md` 或新的 Provider 使用文档，并更新 `docs/roadmap.md`。本规格本身不代表云端 ASR 已实现。
