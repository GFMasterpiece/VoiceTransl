# 输入节点资源清单与编号输出

状态：Implemented（2026-11-06，Windows 本机验收）。批导入已整合至音频输入节点，清单中的每份音频分别应用工作流，输出使用前缀与稳定编号。

## 目标与范围

导入、资源选择、源语言及清单配置在音频输入节点内完成。一次运行按已保存清单决定单次运行或服务端批次，继续复用已有批次调度、取消、重试、历史和 ZIP，不新增另一套队列。批次面板收敛为记录管理，画布上的直接运行与运行记录面板共用同一执行入口。

节点之间继续传递单份音频；不引入音频列表端口、多输入混音、循环节点、子图、真实 Provider 或目录监听。导入和上传不启动处理，先完成配置、校验和保存，再明确运行。

## 资源清单与兼容

- 旧输入配置 `{}` 继续表示当前音频上下文，`{audio_id: ...}` 保持固定单资源；读取旧图不自动补字段或改为清单模式。
- 新配置 `{audio_ids: [...]}` 表示有序资源清单，ID 唯一、归属当前项目，最多 10000；与 `audio_id` 互斥。允许保存 `[]` 以继续编辑空图，运行时明确报空清单，不能回退到当前焦点音频。
- 清单只保存服务端资源 ID；本机绝对路径、浏览器 File、上传中状态不进入图。改变选中的音频或顺序属于执行语义变更，生成新的工作流版本；布局及节点尺寸仍不改变执行版本。
- 节点支持多文件、反复添加多个文件夹、可选递归、默认及逐项源语言、项目已有资源、排除、移除和上传重试。限制来自上传策略，来源目录沿用已有 origin 元数据。
- 上传成功先保存项目资源，再在释放上传锁后同步选中 ID；失败和排除项不会丢弃成功资源，也不能在运行时静默跳过仍选中的待上传/失败文件。
- 清单编辑可撤销/重做；撤销只改变绑定，不删除已经上传的源文件。加载和撤销按图中 ID 顺序重建资源行，保留会话中的待上传文件；缺失资源显示错误并阻止运行，不能悄悄清空绑定。
- 成功清单随图保存和刷新恢复，未上传 File 仅在编辑器会话保留，离开/刷新有保护。跨项目复制与 JSON 导入导出按资源声明同时清除单项和集合绑定。

## 能力目录

持久化 schema 维持 `1.0`，工作流能力目录升级至 `1.6`。`presentation.resource_input` 包含 `{resource_type,config_key,collection_key}`；集合键可空，内置音频输入使用 `audio_ids`。集合字段声明为 JSON，单项与集合资源绑定都由专用资源控件编辑，不自动开放参数线。

字段新增可空 `creation_default`，专供新建节点；`default` 继续描述缺失字段的读取/控件默认。新建时使用非空 creation_default，否则使用 default；不用于读取旧图、旧历史或替换快照中的配置。客户端兼容既有 capability `1.2–1.5` 的单项资源声明，严格校验 `1.6` 的新形状，未知或错误目录不降级。

节点识别、资源键、隐藏字段、默认值及输出模式都来自后端声明；前端不新增节点类型、格式或模式的业务白名单。集合上限由后端统一用于图验证和批次请求，前端不另写数量上限。

## 统一执行

- 显式空清单不能运行；一项走原逐音频运行接口，多项提交原批次接口，保持清单顺序。旧 `{}` 或 `audio_id` 仍走原单次逻辑。
- 前端只负责选择交互入口，后端仍校验完整清单。普通单次 API 遇多项返回 `INPUT_AUDIO_COLLECTION`，空清单返回 `INPUT_AUDIO_COLLECTION_EMPTY`，单项与路由不一致返回 `INPUT_AUDIO_MISMATCH`。
- 图内有显式清单时，初次批次请求的 audio_ids 必须与其内容及顺序完全一致，否则返回 `BATCH_AUDIO_COLLECTION_MISMATCH`；不能漏跑或乱序。旧 `{}` 的批次 API 请求继续兼容，旧固定单项绑定仍保持原批次拒绝语义。
- 批次内部对子运行验证当前音频属于冻结清单，重试允许原清单的失败/中断子集。冻结图保留完整原清单，不为每个子运行重写输入配置。
- 运行前检查图已保存、资源就绪、上传/提交/编辑手势等冲突；批次子运行和普通运行继续使用既有不同的编辑/导航保护。批次面板只保留进度、历史、明细、取消、重试、未确认请求恢复和 ZIP 下载。

## 输出命名与稳定编号

音频/文本输出继续使用 `filename_stem`，新增 `naming_mode=exact|prefix_sequence`：

- 缺少模式的已保存旧图及显式 exact 按原名称输出。
- 新默认图的输出显式采用 prefix_sequence，新添加输出节点通过 creation_default 选择该模式；未曾保存图的项目使用当前默认图，已有持久图和历史不补写。
- prefix_sequence 把字段作为前缀，生成 `prefix_00001`；音频使用实际后缀，文本仍由 format 决定扩展名。原 filename_stem 参数线继续适用，模式本身不开放参数线。
- 编号由后端在批次创建时按清单固定；不使用完成顺序、文件扫描或随机编号。新 `BatchItem.sequence` 为 1-based，重试保留原序号，即使只重试第 2、4 项也保持 00002、00004。
- 旧批次缺少 sequence 时只在新建重试中按其原 index+1 建立序号，不补写原批次。有效序号必须唯一，可有间隙，不能要求小于当前重试项数。
- 子运行保存可空 `batch_item_sequence`。独立单次运行在编号模式下使用 00001；编号模式的批次运行缺少有效序号时明确失败，不能读取最新清单推算。
- 实际完整文件名进入 artifact，配置和 effective_config 保留用户前缀及模式，不能把拼接结果回写图。旧产物不重命名，各运行及节点继续隔离保存。

命名规则集中在服务端共用工具，音频和文本输出不分别维护计数器；前缀沿用安全文件名校验，自动拼接不静默截断合法值，不允许覆盖源文件、其他节点或旧运行。
