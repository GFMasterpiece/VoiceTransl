# 节点工作流第二里程碑：音频预处理

> 状态：Implemented（2026-10-28 完成实现、全量回归及真实 FFmpeg 联调）。完整编辑器仍为 Draft。

## 范围与兼容

在现有节点工作流增加 `preprocess`，支持音频直出、预处理后输出及两者分支并存。不替换旧五阶段，不迁移旧配置，不修改源文件或旧运行。本轮不实现 ASR、文本/视频节点、汇合、缓存复用、指定节点重跑或历史清理。

图仍为项目级、一个 `audio_input`、至少一个 `audio_output`；可含多个预处理节点或串联预处理。端口名/类型仍为 `audio`。输入无入边，输出无出边；每个预处理和输出恰好一条入边。非输出节点必须能到达输出，所有节点从唯一输入可达；拒绝孤立节点、环、多输入及未知类型。无预处理的旧图不变。

## 配置与结果

`preprocess.config` 复用 `PreprocessConfig`：`provider` 为 `mock` 或 `ffmpeg`，默认 `mock`；`sample_rate` 默认 16000，范围 8000–192000；`channels` 默认 1，可为 1/2；`preserve_original` 默认 true。该兼容字段为 false 时也不能删除或覆盖源文件，界面需说明。拒绝未知字段、未知 Provider、任意命令/路径。保存时补齐默认值，省略默认值与显式默认值的执行语义相同。

- Mock 生成独立的原字节副本，不实际重采样/声道转换；界面必须说明它仅验证链路。
- FFmpeg 复用现有预处理 Provider/配置，由服务端配置可执行文件，生成独立 WAV；失败不回退 Mock。命令不经过 shell，不接受用户附加参数。
- 每个节点读取其直接上游的音频文件，不一律读取源音频。输出节点复制直接上游的字节，后缀及媒体类型来自该上游；FFmpeg 下游为 `.wav` / `audio/wav`，Mock 下游保留上游类型。
- 预处理成功时保存与现有格式一致的 audio artifact（大小、SHA256、服务端下载地址），文件放在该运行/节点独立目录。复用已有 `outputs/{node_id}` 元数据/下载路由，允许下载预处理产物；输入仍无下载产物。

## 执行与失败

按图依赖拓扑顺序执行，不能依赖数组顺序或 ID 排序。保持现有单次图运行占用一个全局并发名额；本轮不增加节点并行调度。

- 失败节点为 failed，其依赖下游为 blocked；独立直出/其他分支继续。按最终输出聚合：全部输出成功为 completed，部分成功为 partial，无输出成功为 failed。
- 节点成功立即持久化；每次运行保存不可变图和完整节点配置快照，不覆盖历史。
- 取消、服务关闭必须等待复制线程/FFmpeg 进程退出，不能提前释放音频忙碌边界或晚发布文件；已完成节点保留，未完成临时文件清理。重启仍标 interrupted，不自动续跑。
- FFmpeg 写同节点目录临时 WAV，退出成功并校验文件后再同步/原子发布；超时采用服务端固定 300 秒限制，取消/超时终止并回收子进程。错误稳定且不向客户端暴露绝对路径或原始 stderr。

## 前端与验收

保留现有视觉与旧 Pipeline；增加预处理节点入口及独立设置（Provider、采样率、声道，源文件始终保留说明）。预处理有输入/输出端口，可连输入/预处理到预处理/输出；非法方向和环不能连接。新增节点不得静默重接原有输出，用户显式编辑连线；可提供清晰的选中节点/端口连接操作。配置保存、脏草稿离开、不可变快照、运行只读、过期请求隔离继续有效。

测试覆盖直出兼容、混合分支、串联/乱序图、不同上游字节/类型、配置默认值与版本、失败阻塞/独立分支、缺失 FFmpeg、取消/关闭/超时、历史下载和安全；前端覆盖节点配置、连接/删除、无效草稿、运行状态和预处理产物下载。全量 pytest/Ruff、前端测试/构建及真实 FFmpeg 合成音频联调通过后更新实际文档与状态，不自动提交 Git。
