# 项目素材库、音频组与多输入执行

状态：Implemented · 2026-11-10（Windows 本机、模拟服务及 ego-browser 验收）

## 目标与边界

项目统一保存上传音频；音频组引用项目素材并维护顺序、普通背景文本和关联模式。画布允许多个音频输入，各自绑定一个组。支持运行某个输入或整个画布，每项仍有独立音频、时间轴、运行和产物。

本轮提供素材上传/浏览、组管理、显式背景读取、多源分支与组内顺序调度。Agent 全文分析、自动术语抽取、前序译文记忆、多组隐式配对或混音不在本轮实现范围。组背景由普通字符串接入翻译 context，不恢复固定的语言/术语表单。

## 素材与组

- 音频复用原项目 AudioAsset 与上传接口，不搬迁、复制或重新上传已有素材。上传只新增素材，不自动修改输入绑定或启动运行。
- 每个组保存于项目 `audio-groups/{group_id}.json`，独立 schema `1.0`。字段：`id,revision,name,audio_ids,background,mode,created_at,updated_at`。ID 为稳定 `grp_` 加 32 位十六进制；revision 从 1 开始。
- 成员 ID 同项目、有序、唯一，最多 10000；允许空组草稿。不同组可以引用同一素材。背景沿用 64 KiB UTF-8 文本边界，不解析固定业务字段。
- mode 为 `independent`、`shared`、`continuous`。前两种并行，continuous 同一输入分支中按成员顺序执行。本轮 shared/continuous 均只读取显式背景，不暗中生成或更新剧情记忆。
- 组编辑采用完整替换及 expected_revision 乐观锁，失败保留客户端草稿。组资源 revision 与图的 workflow_revision 独立。
- 移出成员、删除输入节点或删除组不删除音频。当前保存图的声明式组引用阻止删除组；历史及排队快照已有完整背景和成员，不阻止删除。组编辑不修改正在执行的快照。
- 本轮不增加音频物理删除、源语言修改或跨项目资源引用。

## API

相对 `/api/v1/projects/{pid}`：

| 方法与路径 | 请求与响应 |
| --- | --- |
| GET `/audios` | 提供 limit/offset 时返回 items/total/limit/offset，limit 1–200；未提供 limit 保留旧 items 形状，offset 必须为 0 |
| GET `/audio-groups` | 分页摘要 items/total/limit/offset，默认 20、最大 100；摘要省略背景及成员数组，含 audio_count |
| POST `/audio-groups` | name 必填，audio_ids/background/mode 可缺省；201 完整组 |
| GET `/audio-groups/{gid}` | 完整组 |
| PUT `/audio-groups/{gid}` | expected_revision/name/audio_ids/background/mode；成功 revision+1 |
| DELETE `/audio-groups/{gid}?expected_revision=N` | 204；版本冲突或保存图引用返回 409 |

组不存在、版本冲突、组被引用、成员不存在及存储失败分别返回稳定错误，不静默创建空组或覆盖旧版本。CRUD 与运行冻结共用项目 mutation_lock；组存储内部读取不重复取得同一异步锁。

普通单运行 API 对多成员组返回 INPUT_AUDIO_COLLECTION，不能任选一个成员绕过连续前驱；成员只有一项时允许。批次内部调度或明确选择来源历史的节点重跑允许单项，不修改原组。

## 节点与来源范围

- 新建音频输入默认 `group_id:""`，组未选择时可保存草稿、不可执行。取消音频源单实例限制，保留目录声明的节点/边总量限制。源节点可删除，保存有效图仍至少有一个源和一个终端。
- 当前已保存 4.0 的 `{}`、audio_id、audio_ids 继续按原含义执行，和 group_id 互斥；不读旧 v1–v3 文件，不迁移或改写现有资源及历史。新建节点不再复制旧上传大表单。
- 独立组资料读取节点显式引用 group_id，输出既有 string。只从本次运行的 group_snapshots 读取背景，不执行时补读当前组，不内置翻译语言或词表字段。
- 资源控件、组字段及复制/导出剥离均由目录声明。前端与通用运行器不根据内置节点类型猜测角色。背景引用也参与资源归属、冻结和执行指纹。
- 唯一 scope planner 按全部数据/参数边传播来源。不同来源汇合明确拒绝，不默认按索引配对或生成笛卡尔积。同一源内分支汇合保持可用；多个源可共用没有来源依赖的配置节点。
- 执行某源的所有后代及其必要配置祖先，其他节点为 skipped。校验、配置求值、连接冻结、执行、取消、checkpoint 与重跑使用同一范围，不能只修改前端的实例上限。

## 统一运行与调度

扩展现有 POST `/batches`：保留原 workflow_revision/audio_ids/request_id 请求。新请求为 workflow_revision/request_id/target，可带 context_audio_id 及 expected_group_revisions。target 是 `{kind:"source",node_id}` 或 `{kind:"canvas"}`；与旧 audio_ids 互斥。

新 target 请求始终返回一个 BatchSummary，包括只有一个成员的组；每项仍生成独立 WorkflowRun。前端不得逐文件或逐组循环创建批次。旧单源单运行接口保留，多源使用旧单运行接口时须显式提供 source_node_id。

- 提交在同一项目锁内解析选中来源、冻结图、实际用到的组版本/顺序/背景与连接凭据，先完整校验再发布批次和预留。
- 同一画布按源顺序、各组成员顺序建立确定清单。每项记录 source_node_id、source_sequence 和音频身份，全局 sequence 决定原编号导出，组内剧情顺序与全局导出编号分开解释。
- 同素材跨源是明确选择的不同任务，不去重丢掉分支。仍遵守同音频互斥，在同一批次中顺序派发，等该音频所有项结束才释放预留。不同批次或单运行仍受 AUDIO_BUSY 限制。
- 保留同项目一个活动批次；一个画布批次内部允许独立组并行。dispatcher 只派发 ready 项，不能为了等待连续组或重复音频持有全局执行许可或忙循环。
- continuous 同来源前项 completed 后才开始下一项；前项失败、部分完成、取消或中断时，依赖后项标 blocked 并给出原因，其他组继续。重试显式创建新批次，保留原背景/清单/序号及已有成功前驱证据，不重新请求成功前项。retry 新增 include_partial，默认 false；与 include_cancelled 一样仅显式勾选才重试对应项。blocked 的必需前驱未成功且未纳入本次重试时，提交前报 BATCH_DEPENDENCY_NOT_COMPLETED，不越过前项或发起部分请求。
- 取消、服务关闭和恢复沿用原清理语义；只取消当前连续项也不能悄悄启动后续项。
- 历史、明细、ZIP 和重跑能定位来源与冻结组，不因两个输入用了同一素材而混淆结果。历史摘要的可选 source_node_id/source_group_name 从冻结图派生，不读当前组名。重跑须匹配来源，资料变化进入递归指纹，不自动扩大云调用范围。

## 版本与界面

组为独立资源 1.0；图/运行/批次/设置保持 4.0，目录升级 1.19。快照 group_snapshots、运行来源及批次项来源为向后可选扩展，空值序列化省略；读取旧 4.0 counts 时允许缺少新增 blocked 项，不批量改写旧文件。历史旧版本不恢复。

画布工具栏打开项目素材弹窗，素材页负责文件/目录上传、源语言、筛选及分页；组页负责名称、成员、排序、背景及模式。节点提供组选择、短摘要、管理与运行此输入；主按钮运行画布。组保存、图保存和运行状态分别展示，不用组修改伪造图 revision。

组草稿、待传 File、上传和不确定提交保留原离开保护；切换语言、组、标签、目录刷新不清空未保存内容或 Key。错误在当前操作面板内可见；冲突不覆盖用户输入。复用全局对话框、语言候选、后端上传策略及现有编辑锁。

## 验收

- 已有项目素材复用；组增删改、跨组引用、顺序与分页、冲突和非法成员、保存图引用保护、错误不改原文件。
- 两输入分支互不混音频，共享服务/模型/普通配置正常；任意数据或参数边跨源汇合明确拒绝；未运行来源不触发云请求或无关配置错误。
- 单组/全画布均一次提交；同素材跨组各有独立结果且不并行冲突；背景读取来自快照，修改当前组不影响排队项。
- continuous 顺序、失败阻断及重试、独立组并行、取消/关闭回收、重启中断和幂等丢响应。
- 导出/复制剥离组引用；来源和背景参与 checkpoint，组更新后不复用旧语义，旧4.0单源图/设置/历史保持可读且不补写。
- Windows 前后端全量检查及隔离模拟服务的真实浏览器素材/组/多源/背景/批次验收，不调用付费服务。
