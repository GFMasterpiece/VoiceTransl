# 兼容性与扩展性整改

> 状态：Approved（2026-10-29 用户确认）。本文件记录验收边界，未通过验证的条目不得描述为已实现。云端 ASR 仍另按规格实施，不在本次顺带接入。

> 范围更新（2026-10-29）：后续用户要求已退役固定 Pipeline 和全部真实节点 Provider，当前只保留音频直通与 Mock 验证。下文的真实服务发现、HTTP 翻译和进程生命周期验收约束保留为重新接入时的要求，不代表当前支持或本轮已经验证；当前能力以 `docs/architecture.md` 为准。

## 范围与决定

1. **Schema：**当前仅接受与当前版本完全一致的 `schema_version`，不实现跨版本迁移；显式不同版本不得读取后降级保存。持久化文件的版本缺失或无效应明确拒绝，不改写原文件。新对象由当前版本创建。
2. **对齐配置：**本次不改变现有 Mock/fallback 行为，对齐配置的实际生效语义留待后续专门规格处理。
3. **能力单一来源：**ASR 后端等可变能力只在一处配置/注册或查询，其余校验、Provider、API、前端自动消费或派生；不得重复维护永久白名单。能力发现失败必须明确提示，不静默使用预置列表冒充成功。
4. **翻译取消：**取消需终止本地正在进行的请求、回收执行资源，结束后不能遗留仍在执行的请求线程；关闭和超时遵守同样边界。Python 线程不能安全强杀，允许改用真正可取消的异步传输或可终止并回收的隔离 worker；不能承诺撤销服务商已收到的计算。
5. **附加参数：**服务商/模型可选字段统一通过 `additional_parameters` 明确配置，默认 `{}`，默认不发送 temperature、response_format、max_tokens 等可选参数。核心模型/输入、URL、认证和密钥字段不得被附加参数覆盖；参数必须是受限、合法 JSON。不自动注入未知能力，不为兼容而静默重试改变语义。旧显式字段兼容策略需记录。
6. **跨系统：**实现必须覆盖支持的操作系统。平台差异集中于有明确分支、清理保证和测试的适配层；禁止无保护使用仅某一系统可用的 API。至少验证 Linux 和 Windows 的关键文件与进程生命周期；无法实机验证的平台必须标明。
7. **语言：**创建项目由用户明确提供源语言和目标语言，校验非空、合法长度、不同语言，不猜测用户目标；新增音频明确提供源语言，目标继承/覆盖不改变既有项目语义。`zh-CN` 等区域语言代码必须能够创建并加载有效配置。
8. **导出：**支持安全自定义命名，结构化结果描述格式、语言、是否双语、文件和下载元数据；不再靠 `ja-zh` 等文件名前缀推断语义。旧默认文件名和旧输出下载保持兼容；拒绝目录穿越、系统保留文件名、冲突及覆盖源文件。
9. **节点契约：**节点类型、端口、配置 schema、终端标志和执行器由权威注册表定义；通用图校验、调度和前端从目录派生，不新增散落的类型条件分支。新增已有数据类型的节点应通过一次注册及独立执行器/编辑器接入，不修改通用调度器。未知节点/端口明确报错，不能通过取消安全边界实现扩展。当前已支持的节点数量/语义不因本次变化自动扩展成未实现能力。
10. **分页：**项目列表提供 `limit`/`offset`，返回 `items,total,limit,offset`，稳定排序；前端能切换分页，超过 200 项仍可访问。默认页长 20，最大 100，拒绝非法参数。历史分页性能优化另行处理，不以“已分页”声称不扫描全量。

## 验收

- 全量后端测试、Ruff、前端测试与构建通过；不修改现有运行数据、不提交 data/ 或 scripts/，未经用户授权不提交 Git。
- 不同/缺失版本拒绝并确认文件不被改写，覆盖嵌套快照和服务启动恢复。
- 同协议非预置 ASR 能力只需一处配置/发现，前后端同步；查询失败与非法标识符明确处理。
- 翻译默认请求不带可选字段，显式参数保留，核心/认证覆盖被拒绝；取消、超时、关闭时无遗留 worker。
- 关键跨平台适配场景、`zh-CN` 创建、双语和自定义命名、结构化产物及旧下载回归。
- 注册一个测试节点验证图校验/调度/目录同步不需修改通用分支；旧图、历史快照、队列捕获和安全校验回归。
- 项目列表首/中/末页、空页、非法分页、创建/删除刷新及过期响应隔离。

## 兼容性说明

用户已确认严格版本、语言必填和分页入口调整；旧客户端缺少新增必填字段应明确返回 422，而不是填充猜测默认。只读历史不静默迁移。仍属同版本的现有配置与任务保持既有含义；任何无法保持的情况需单独说明而不是统一重写历史。
