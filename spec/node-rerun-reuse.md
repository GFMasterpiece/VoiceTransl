# 节点级重跑与结果复用

状态：**Implemented**（2026-11-09，Windows 本机验收）。从当前保存图的指定节点强制重算该节点及下游，复用已验证的上游结果，创建独立新运行。

## 范围

- 首版以同项目、同音频的一份终态历史运行作为显式来源，包括失败、取消或中断运行中已经成功的节点。来源为活动运行时拒绝；不自动选择最新记录。
- 批次历史的单份音频也可以独立重跑，保持原序号，原批次条目、统计、ZIP 与旧运行不变。本轮不提供整批节点重跑或自动从任意缓存挑选结果。
- 当前图须先保存且整体结构、字段配置合法。节点重跑使用新图快照；普通运行仍执行全图，不自动跳过有效结果。
- 执行集合 E 为选中节点及全部后代，包括参数连线产生的依赖。E 所需的外部祖先闭包 A 只验证与复用，其他节点明确标记未参与。
- A 内任一结果缺失、损坏或失效时阻止启动，指出原因及需要前移的节点；不自动扩大执行范围。E 内节点全部重新执行，即使已有有效结果。

## 每节点结果快照

- 每个成功节点发布命名输出的 typed checkpoint，包含实际逻辑类型、codec 标识及版本、有限 JSON payload、受控文件描述符。sidecar 文件与大输出分开，运行 JSON 仅记录版本、指纹、大小及摘要。
- 基本类型、audio、transcript 在类型注册中声明 codec；source_info 自然保存多个 string 输出。通用调度器不按节点类型分派序列化。
- `NodeData` 可指定实际 `type_id`，省略时沿端口声明类型；转接保留实际类型并验证兼容。子类型不自动继承父 codec，避免丢失附加语义；扩展可注册自己的 codec，无需修改通用执行器。
- 音频文件、完整转写和终端 artifact 各按自身契约保存，不从 TXT/SRT 等展示产物猜测上游数据，不序列化 Python 对象、任意绝对路径、密钥或临时 URL。
- 实际存储失败不能发布 completed；不支持 codec 的扩展仍可正常运行，但不冒充具有可复用结果。
- checkpoint 及相关输出原子发布后才保存 completed 状态。保留可取消的分块读写与线程回收，不在事件循环内无界读取大音频。

## 有效性

- 首次执行记录源音频实际 SHA-256、大小、音频 ID 及相关 source 元数据，保守统一纳入当前文件名、语言与来源信息。重跑重新校验实际内容，不能仅比较 ID、文件名或大小。
- 节点指纹包括身份/类型、声明的执行版本、完整手填配置及实际执行配置、所有入边的源/目标端口映射、递归上游指纹和输出语义摘要。接线字段的手填后备值也参与比较。
- 位置、尺寸、显示标签、边 ID 和新运行文件位置不改变结果身份；文件语义摘要使用内容哈希、大小及类型信息，不含运行路径或 artifact ID。
- codec 版本、节点执行版本、端口及参数来源变化均明确失效。修改实现语义需更新执行版本，不能声称可检测同 URL 远端模型的不可见变化。
- E 中实际调用的云节点冻结并验证自身密钥版本；复用 A 仅比较原配置中的不透明凭据引用，不重新调用服务。无关分支不因未设置 Key 强迫重跑其他部分。

## 新运行隔离

- 复用的文件、checkpoint 和 artifact 复制到新运行自身目录，检查大小和摘要；保留真实扩展名及媒体信息，生成新 artifact ID 与预览/下载地址。
- 不使用硬链接、软链接或指向旧运行文件的路径代替副本。原运行记录和产物原字节不变，新运行后不依赖旧结果继续存在。
- 排队启动前再次验证被冻结的复用输入，变化或丢失时明确失败，不补读最新历史，也不调用被复用的上游服务。
- `execution_kind` 区分实际执行和复用，`reused_from` 记录来源节点；无关节点为 `skipped`。整体成功仅按本次 E 中的终端聚合，没有终端时检查 E 的全部节点，不能因空集合误判成功。
- 批次历史单项重跑记录来源及原固定编号，作为新独立运行存在，不归入原批次管理。

## 接口与界面

- 能力目录为 `1.14`，持久化仍 `1.0`；旧新增字段为可空且序列化省略，不回填旧 checkpoint。缺少必要 checkpoint 的旧历史明确不可复用，仍可正常查看、下载或发起全图新运行。
- `POST /projects/{pid}/audios/{aid}/workflow-runs/plan` 接受 `{workflow_revision,rerun:{source_run_id,from_node_id}}`，返回 `{valid,execute_node_ids,reuse_node_ids,skipped_node_ids,issues}`；issues 含稳定 code、message、可选 node_id 和 restart_node_ids。
- 原单音频运行 POST 接受上述字段及稳定 `request_id`；重跑必须带请求 ID。相同请求重放返回原运行，内容不同则冲突，重放判定先于忙碌和新修订校验，防止丢响应后重复调用服务。
- 预检只读且可关闭，提交在既有项目/音频锁内重新规划并验证，再创建新运行。当前输入为多项清单时，只允许目标音频属于当前绑定的单项重跑，不更改图清单。
- 节点右键提供“从此处重新运行”，使用当前选定历史。紧凑弹窗显示来源音频、执行/复用范围及必要错误，提交时防重复，失败保留可重试请求；复用和未参与状态在画布/历史中正确显示。
- 切项目、弹窗关闭和请求迟回不影响其他项目草稿、密码及 File；复制剪切粘贴遵循[编辑器操作](editor-operations.md)。

## 验收

- 修改输出名称或格式后重跑输出，上游 ASR 调用次数不增加；选中 ASR 则强制重算它和全部后代。
- 分支、汇合侧输入、多个命名端口、参数来源及基本类型可复用；无关分支未参与，源/上游失效不自动补跑。
- 同大小音频篡改、checkpoint/文件损坏、codec/执行版本改变、连接及配置变化、旧无 checkpoint、忙碌及来源归属错误均拒绝。
- 新运行复制与原文件不变、原来源删除后的新运行独立、排队输入损坏、取消/超时/关闭回收、失败来源的完成节点可复用。
- 提交丢响应的同请求重放、批次单项固定编号、旧图/历史兼容及原全图/批次运行回归。
- 前后端全量、Ruff、构建和 Windows 隔离浏览器验证；不调用付费接口，未实测平台明确说明。

## 验收记录与限制

- Windows 后端全量 `666 passed, 7 skipped`，Ruff check 与 format check（110 文件）通过；前端全量 482 项及生产构建通过。跳过项包含当前环境缺少符号链接权限的路径测试，不代表对应场景已通过；Linux/macOS 本轮未实测。
- 真实 Edge、独立 HTTP 假平台和合成音频完成五次运行：初跑一次识别，三次输出重跑与丢响应重放均不新增识别，从 ASR 起点重跑才增加一次识别；VTT 毫秒时间正确，必要上游显示复用，无关分支未参与，旧运行原字节不变。移走原来源运行后，新运行仍可独立复用。
- 两文件批次的第二项独立重跑仍导出 `batch_00002.txt`，原批次及子运行原字节不变；仅改布局和边 ID 不失效。同大小源文件篡改、checkpoint 损坏和上游配置变化均拒绝，返回定位起点且没有追加识别调用。
- 桌面、390px 窄屏、中英文预检与错误入口通过；剪切、保护音频源、一步撤销、内部连线粘贴、凭据剥离及原生文字快捷键通过，浏览器异常为零。取消/关闭准备、排队副本损坏、run.json 提交后元数据失败及幂等回归由后端定向测试覆盖。
- 首版仅支持单音频（含批次单项）重跑，不提供整批起点重跑、自动缓存调度或历史清理。sidecar 上限 16 MiB，文件物理副本未去重，会增加磁盘占用；提交返回前需完成上游副本准备，大文件会增加等待时间。界面在当前编辑会话保留失败请求标识，未承诺刷新后恢复待确认请求；接口自身支持原请求 ID 重放。未使用真实账户或付费服务验收。
