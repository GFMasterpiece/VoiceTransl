# 节点资源与独立预览

状态：Implemented（2026-11-01，Windows 本机验收）。用户已确认将音频添加入口移入输入节点，并将预览拆成独立节点；本轮实现音频和文本预览。

## 范围

- 创建空项目后即可进入工作流。音频输入节点负责上传新音频或选择项目已有资源；上传不自动运行。
- 继续支持一个音频输入节点、单输入端口及分支，不扩展多源汇合、视频、真实模型、缓存续跑或文件清理。
- 音频预览和文本预览是独立终端节点，可接在兼容的任意分支。只有预览、没有文件导出节点的图可以运行。
- 输入负责获取资源，预览负责展示运行结果，导出负责生成用户配置的文件；预览节点不要求配置导出文件名。

## 资源和运行

1. 空项目创建仅填写名称，不要求语言或上传音频。2026-11-01 后续用户确认将语言配置移入相关节点；旧语言字段和 multipart 上传创建接口保留兼容，新建页不再提供批量导入入口。
2. 空项目 `source=null`、`audios=[]`，可以保存项目图；没有可用输入音频时不能运行。不制造空文件或虚假主音频。
3. 上传每次创建独立音频资源，源语言显式提供；输入节点通过稳定的 `audio_id` 引用资源，不保存浏览器文件对象或本机路径。替换绑定不覆盖源文件。
4. 输入节点显式绑定必须属于当前项目；启动路由的音频 ID 必须与绑定一致。校验及保存拒绝跨项目、非法或不存在的引用。
5. 运行仍按音频隔离，启动时固定图版本、节点配置及音频 ID。以后修改绑定不改变旧运行的输入或产物。
6. 历史查看的音频上下文与显式输入绑定分开；切换历史不改写草稿，开始新运行时使用节点绑定的音频。活动运行期间维持原有锁定与取消边界。
7. 上传失败可重试；上传成功的资源不因绑定保存失败而删除。保存失败保留草稿和已上传资源。

## 能力目录与扩展

- `workflow` capability schema 提升为 `1.3`，前后端配套升级并继续严格拒绝未知版本。项目、工作流和运行的持久化版本仍为 `1.0`。
- 节点目录发布可空 `presentation`，其中 `resource_input` 声明资源种类及配置键，`preview` 声明渲染器。前端根据此元数据选择组件，不按节点类型名称判断上传或预览能力。
- 本轮资源输入声明为 `{resource_type: "audio", config_key: "audio_id"}`；输入配置字段仍由服务端目录发布。
- 本轮 `audio_preview` 接收 `audio`，`text_preview` 接收 `transcript`，均无输出端口。端口兼容性继续由数据类型注册表判断；后续可以为其他文本表示注册使用相同文本渲染器的节点，不将所有数据强制视为同一种 Python 类型。
- 渲染器以标识查找独立组件，本轮实现 `audio` 和 `text`。未知标识明确提示，不能静默套用其他渲染器或自动调用模型。

## 预览与历史

- 成功的预览节点保存按运行及节点隔离的缓存和结构化描述 `{renderer, content_url, media_type}`。音频保存可播放的独立副本，文本保存转写片段的文本表示；缓存属于预览实现，不改变源数据。
- 内容通过受项目、音频、运行和节点边界保护的接口读取，支持音频范围请求；URL 不暴露本机路径，不接受任意文件位置。
- 文本按纯文本展示，不执行 HTML。音频使用受控媒体响应和 `nosniff`，不能直接信任上传的任意 MIME 声明。
- 预览明确关联所选运行及节点类型。草稿与结果不一致时标记历史结果，不把旧运行结果当作当前草稿的新输出。
- 缺失文件、加载失败、浏览器不支持的音频播放应明确提示并允许重试；浏览器展示失败不修改后端运行状态，不影响已成功的其他分支。

## 兼容边界

- 旧项目的 `source` 及虚拟 `aud_primary` 语义保持不变，不搬迁文件；空项目上传的新资源只进入 `audios`，不凭空增加主音频。
- 旧 `audio_input.config={}` 继续绑定该次运行的 `audio_id` 上下文，不在读取旧图或旧快照时补写资源绑定。
- 旧节点记录缺少 `preview` 时按无预览读取；下载、运行历史及旧 Job 的只读兼容入口继续维持既有范围。
- 新资源与展示字段采用可选扩展；不静默迁移 schema，不重写旧配置、工作流修订或终态历史。

## 验收

1. 仅填写名称创建零音频项目后能直接编辑、保存图；项目不被补入默认语言，上传时从输入节点明确提供源语言，成功后选择并运行。
2. 节点上传和失败重试保持草稿；绑定保存和显式音频不匹配、跨项目引用均有明确错误。
3. 音频输入直连音频预览、Mock ASR 连接文本预览均能独立成功，无需导出节点；预览和导出并存时保持分支隔离。
4. 音频播放器可读取范围响应，文本安全显示；刷新后能读取保存的预览，缺失或加载失败可重试。
5. 修改绑定、切换音频历史、查看旧版本及较慢的旧响应不串扰新视图，不覆盖旧快照。
6. 旧项目、旧 `{}` 输入图及无预览的运行继续可读、可执行其原有语义；节点编辑、拖线、网格、取消、忙碌删除、上传重试和安全边界回归通过。
