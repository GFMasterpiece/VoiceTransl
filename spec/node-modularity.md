# 节点模块化与多端口

> 状态：Implemented（2026-11-06，Windows 本机验收）。本轮由用户授权按 ComfyUI 的节点契约与调度方向重构；以下记录首个完整实现范围。

后续参数端口、参数根与目录 `1.5` 的扩展单独维护在[节点参数与连线输入统一](node-parameters.md)，本文保留多端口里程碑的原验收范围。

## 范围与边界

- 通用注册核心、节点契约、内置节点模块和文件发布服务分离；注册核心及调度器不按内置节点类型分派执行。
- 一个节点可声明多个命名输入和输出。端口 ID 表示插槽身份，逻辑 `type_id` 及其父类型、能力和运行时校验表示数据契约；两个不同名称的端口可使用同一类型。
- 当前仍为单源、单项目音频运行，按拓扑顺序串行调度。汇合节点等全部已连接上游完成后执行；本轮不增加混音、真实 Provider 或多音频源功能。
- 仍要求图无环、所有节点从唯一源可达并可到达终端；不在本轮改变草稿保存或执行目标语义。

## 契约

- capability API 顶层版本保持 `1.0`，`workflow.schema_version` 升为 `1.4`；`input_ports`、`output_ports` 保持字符串数组，新增 `required_input_ports`，旧 `required_inbound` 为该数组长度的派生值。前端明确支持旧 `1.2/1.3` 单端口目录，不接受未知版本；`1.4` 的必填端口声明必须是数组，缺失、`null` 或其他类型均报错，不能回退推断；没有必填输入时显式使用 `[]`。
- 后端 `NodeDefinition.required_input_ports` 逐名声明必填输入；未声明时，旧 `required_inbound=0` 表示全可选，其余旧定义按所有已声明输入必填解释。显式命名声明优先；目录不转发可能矛盾的旧计数。
- 每个必填输入恰好一条连接，可选输入零或一条；一个输出可分支到多个输入。同一节点对之间可存在连接不同端口的多条边。
- 执行器按每条边的 `source_port` 取上游值，按 `target_port` 组装当前 `NodeData`。校验输入和全部已声明输出的运行时类型；节点不得返回未声明、缺失或类型无效的输出。
- 未连接的可选输入不出现在 `context.inputs` 中；已连接的可选上游失败也会阻断当前节点。无关输出分支继续执行，沿用部分成功、失败和取消语义。
- 执行器通过通用 `NodeExecutionError(code,message)` 报告可展示的错误，通过 `NodeExecutionCancelled` 在完成资源清理后报告取消；调度器不依赖 ASR 等节点专用异常。意外异常仍转换为通用安全错误，不回传 traceback。
- 边端口 ID 的长度与注册约束一致，最多 64 字符。
- 前端按目录顺序为全部端口绘制独立连接点；正反拖线均记录明确的端口 ID。完成合法连接才替换目标端口的原线，取消、无效连接及重复连接不修改其他输入。多端口调用省略端口选择时明确失败，不猜第一个端口。
- 端口区域按行数扩大，设置与预览从全部端口下方开始；最小尺寸、连线锚点及避让使用同一几何计算。可选输入在端口标签中说明。

## 兼容与扩展

- 项目、工作流、运行及嵌套快照的持久化 schema 仍为 `1.0`；旧单端口图、配置、命名、下载和历史记录语义不变，不扫描迁移或改写已有数据。
- 一次节点结果仍最多保存一个 artifact 和一个 preview；多输出首先用于运行时中间值。多个需持久导出的结果连接独立输出节点；不新增未经版本化的多产物存储格式。
- 新增内置节点：独立模块声明配置、输入输出、校验和执行器，在显式组合入口接入；沿用已有数据类型时不修改通用调度器或前端节点类型名单。新逻辑类型和端口显式注册，未知契约明确拒绝。
- 输入资源、密钥和文件路径的既有安全边界保留；不开放通过 API 导入 Python 模块、提交代码或安装第三方节点。
- 参数转换为连线、动态字段、选定输出执行、持久缓存重跑、节点事件和组合子图后续分别细化；不把本轮重构标成这些功能已实现。重跑仍遵循既定的上游失效拒绝启动规则。

## 验收

1. 测试扩展节点实现分叉再汇合，同一节点对经不同端口传递不同值，可选输入省略合法，最终导出与源字节一致；无需调度器类型分支。
2. 缺失必填、重复输入、未知端口、无效结果、环和非法配置明确失败；失败分支阻断汇合且独立输出继续成功。`1.4` 目录拒绝缺失、`null`、非数组及内容矛盾的必填端口声明，合法空数组与可选输入正常解析，旧 `1.2/1.3` 目录继续兼容。
3. 实际画布正向、反向连接指定端口，重连保留其他输入，取消保留旧线；多行端口不遮挡设置，大小与视口操作后连线仍对齐。
4. 默认直通、Mock、资源/预览、保存冲突、取消与关闭清理、旧运行和下载回归通过；编辑布局及移除扩展实现不改写历史快照。
5. 后端全量测试和 Ruff、前端全量测试和构建通过；Windows 本机浏览器检查无运行异常。其他平台未实际运行则明确标注。

验收记录：后端 `pytest -q` 177 passed、2 skipped（Windows 符号链接权限），Ruff 检查及格式检查通过；前端 239 项测试与生产构建通过。独立 Edge 浏览器以真实鼠标验证双向指定端口拖线、重连保留其他输入、取消和环检测、缩放及尺寸调整后的连接点对齐、保存/运行/字节一致下载和语言切换，零浏览器异常；同时修正了侧边尺寸热区遮挡第二个输出端口和无配置节点底部文字越界。Linux 本轮未实测。
